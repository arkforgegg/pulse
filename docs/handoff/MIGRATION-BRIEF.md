# Pulse Nova website — migration brief (for Claude Code)

Read this whole file before touching code. `START-HERE.md` and `QA-RESULTS.md` describe the current (ChatGPT Sites) build; this brief supersedes their deployment instructions.

## Goal

Move the site off ChatGPT Sites (`*.chatgpt.site`, OpenAI's Cloudflare) to Pulse Nova's own **Cloudflare account**, at $0/month, with:

- **Frontend**: static build served by **Cloudflare Workers Static Assets** (free plan).
- **Backend**: one tiny Worker route `POST /api/submit` on the same domain.
- **Storage**: **Google Sheets**, written server-to-server via a **Google Apps Script web app**.
- **No D1, no SSR, no ChatGPT Sites tooling.**

Hard requirement: **preserve the current design, content (EN + 中文) and mobile layout exactly.** This is a re-platform, not a redesign. Do not "improve" copy, spacing, colors or structure.

## Why this shape (don't revert it)

- Mainland-China visitors are a core audience. All Google domains are blocked there, so the **browser must never call Google directly**. Browser → our domain → Worker → Apps Script.
- The page has no server-rendered data, so it can be static. That keeps the Worker to one short request per submission, well inside the free plan's 10 ms CPU limit.
- Apps Script is not exposed publicly in practice: it rejects anything without the shared secret.

## Target architecture

```
Browser ──► https://<domain>/            static assets (index.html, JS, CSS, images, fonts)
        └─► POST https://<domain>/api/submit   Worker
                 ├─ Content-Type must be application/json; Origin must match ALLOWED_ORIGIN
                 ├─ body size cap (e.g. 32 KB)
                 ├─ honeypot field must be empty
                 ├─ Cloudflare Turnstile token verified (siteverify)
                 ├─ zod whitelist of known fields + per-field length caps + email format
                 ├─ direction rules (see "Validation")
                 ├─ neutralise spreadsheet formulas (prefix ' if value starts with = + - @ \t \r)
                 └─ fetch(APPS_SCRIPT_URL, {secret, record}) ──► Apps Script ──► appendRow ──► Google Sheet
```

Rate limiting: add a Cloudflare WAF rate-limit rule for `/api/submit` (document it in the runbook; it's dashboard config, not code). Optionally also use the Workers rate-limit binding.

Admin: **no admin page in this phase.** Pulse Nova staff view the Google Sheet directly (shared per-person via Google accounts). Delete `app/responses/` and the `GET` handler. (Open question for later: if staff in mainland China can't reach Google, add a D1 copy + `/responses` behind Cloudflare Access. Do NOT build this now.)

## Current code (what you're starting from)

- `source/` is a **vinext** (Next.js-on-Vite, beta) app generated by ChatGPT Sites. Real app code is small:
  - `app/page.tsx` (~25 KB, single `"use client"` component — the entire landing page + multi-step form)
  - `app/layout.tsx` (title/description/favicon metadata only)
  - `app/globals.css` (all styling; imports Google Fonts + tailwindcss)
  - `app/api/consultations/route.ts` (POST save to D1 + optional Resend email; GET admin list)
  - `app/responses/page.tsx` (admin UI — to be removed)
  - `public/` images, logos, favicon
- Everything else is Sites scaffolding: `.openai/`, `app/chatgpt-auth.ts`, `build/sites-vite-plugin.*`, `scripts/*`, `examples/`, `db/`, `drizzle/`, `drizzle.config.ts`, `cloudflare-env.d.ts`, `vendor/`, most of `components/ui/*` (check which, if any, `page.tsx` imports; likely none).

## Recommended implementation

Rebuild as a **plain Vite + React SPA** (single page) plus a Worker. This removes the vinext beta dependency and is the simplest static output.

1. New project layout (suggestion):
   ```
   web/            Vite + React + TS; src/App.tsx = ported page.tsx; src/globals.css; public/ assets
   worker/         src/index.ts (fetch handler for /api/submit, falls through to assets)
   apps-script/    Code.gs + appsscript.json (to paste into script.google.com)
   wrangler.jsonc  assets.directory = web/dist, main = worker/src/index.ts,
                   assets.run_worker_first = ["/api/*"], not_found_handling = "single-page-application"
   ```
   A single package at repo root is fine too; keep it simple.
2. Port `page.tsx` **verbatim** into `App.tsx`; only change: the submit fetch URL → `/api/submit`, add the Turnstile widget + token, add the honeypot input (visually hidden, `tabIndex=-1`, `autocomplete="off"`). Keep the existing success/error UI states.
3. Move `<title>`, meta description, favicon from `layout.tsx` into `index.html`. Keep `<html lang="en">`.
4. Keep `globals.css` as is, **except self-host the fonts**: Inter (400/500/600/700), Manrope (500/600/700), Noto Sans SC (400/500/600). Google Fonts is blocked in China and currently stalls rendering there. Use `@fontsource/*` packages or downloaded woff2 files; keep the same family names so CSS is unchanged. Noto Sans SC is large — use unicode-range subsets (fontsource does this).
5. If `globals.css` relies on Tailwind (`@import "tailwindcss"`), keep Tailwind 4 via `@tailwindcss/vite`. Remove the vendored shadcn css only if nothing uses it.
6. Remove the Resend email feature unless trivially kept: **default = drop it** and instead have Apps Script send the notification with `MailApp.sendEmail` to `NOTIFY_EMAIL` (free, no extra secret). Make the recipient a Script Property.

### Form fields (whitelist)

From `page.tsx` `name=` attributes:

```
consultationDirection, companyName, contactName, email, contactChannel, website, industry,
companyIntro, sellingPoints, priorityOfferings, priceRange, currentMarkets, regions,
chinaStage, chinaEntity, currentChinaSetup, trademark, previousActivities,
targetMarkets, overseasStage, overseasSetup,
consultationFocus, supportInterest, resourcesNeeded, priorityGoal, challenges,
targetContacts, timeline, budget, meetingFormat, language, preferredDate, preferredTime, consent
```

Some are multi-select (the client sends `string | string[]`); join arrays with `", "`. Re-check against `page.tsx` before finalising; if the code has a field not in this list, include it.

### Validation (keep current server behaviour)

- Required: `companyName`, `contactName`, `email`, `consent`.
- `consultationDirection` ∈ {`Entering China`, `Going global`, `Both directions`}.
- If direction ≠ `Entering China`: `targetMarkets` and `overseasStage` required.
- Length caps: names 200, email 240, contactChannel 120, other fields 4000.
- Unknown keys: drop silently.
- Return `201 {ok:true}` on success, `400 {error}` on validation failure, `502 {error}` if Apps Script fails. The client already shows a generic error on non-2xx.

### Apps Script

- `doPost(e)`: parse `e.postData.contents`, check `body.secret === PropertiesService.getScriptProperties().getProperty('SHARED_SECRET')` (constant-time not available; fine — secret is long and server-held). Reject otherwise.
- Use `LockService` around the append.
- Append a row with a fixed column order: `timestamp (ISO, Asia/Singapore)`, `status` (= "new"), then every whitelisted field in the order above. Create the header row if the sheet is empty.
- Write values as **plain text** (`setNumberFormat('@')` on the range, or `appendRow` with values already prefixed by the Worker). Never evaluate user input as formulas.
- Optionally `MailApp.sendEmail(NOTIFY_EMAIL, "New consultation · <companyName>", <plain-text summary>)`; failures must not fail the append.
- Return JSON `{ok:true}` via `ContentService`.
- Deploy as web app: *Execute as: me (the Pulse Nova Workspace account)*, *Who has access: Anyone*. The script and sheet must belong to a **company** Google account, not a personal one.

### Worker secrets / vars

```
APPS_SCRIPT_URL      secret   web app /exec URL
APPS_SCRIPT_SECRET   secret   long random string, same as Script Property SHARED_SECRET
TURNSTILE_SECRET     secret
TURNSTILE_SITE_KEY   var      (also needed at build time for the client: VITE_TURNSTILE_SITE_KEY)
ALLOWED_ORIGIN       var      e.g. https://china.pulsenova.gg (allow localhost in dev)
```

Apps Script `/exec` responds with a 302 to `script.googleusercontent.com`; use `redirect: "follow"` and check the final JSON.

### Security headers (set in the Worker for all responses, incl. assets)

`Content-Security-Policy` (self + `challenges.cloudflare.com` for Turnstile script/frame; no Google Fonts since self-hosted), `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `frame-ancestors 'none'` (in CSP), `Strict-Transport-Security: max-age=31536000`. Verify Turnstile still renders under the CSP.

## Verification (must do before handing back)

1. `npm run build` (or pnpm) succeeds; `wrangler dev` serves the site and `/api/submit`.
2. **Visual parity**: run the ORIGINAL vinext app and the NEW app side by side and take Playwright screenshots at 390×844 and 1440×900 of the full page, plus the form with each direction selected (Entering China / Going global / Both). Diff them; differences should be none beyond font rendering. Chromium is at `/opt/pw-browsers` (`PLAYWRIGHT_BROWSERS_PATH` set; don't run `playwright install`). If the original won't run, fall back to screenshots of the live site `https://pulse-nova-china-advisory.shanshan9606.chatgpt.site` if reachable.
3. Worker tests (vitest + `@cloudflare/vitest-pool-workers` or plain unit tests with a mocked `fetch`): valid submission for each of the 3 directions → Apps Script called with whitelisted, formula-neutralised fields; missing required → 400; going-global without targetMarkets → 400; wrong Origin / wrong content-type → 403/415; honeypot filled → 200 fake-success but no Apps Script call; oversize body → 413; Turnstile fail → 403; Apps Script failure → 502.
4. Click-through in a browser: switching direction shows/hides the right fields; client-side validation; success and error states.
5. Lint + typecheck clean.

You cannot reach the real Apps Script or Turnstile from the sandbox; mock them and use Turnstile's documented test keys in dev.
